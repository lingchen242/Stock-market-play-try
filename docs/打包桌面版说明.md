# 把《股市模拟》打包成 Windows exe

游戏本体就是一个 HTML 文件，桌面打包要做的就是给它套一个原生窗口。本项目用的是 **Neutralino**：产出一个 **2.62 MB 的单文件 exe**，拷给别人双击就能玩，目标机器不需要装任何东西。

> 仓库里曾经同时维护过一套 Electron 方案（约 70~100 MB，需要下载约 250 MB 的工具链）。因为体积代价太大、游戏又用不到任何原生能力，已经移除，只保留下面这一条路子。

## 目录约定

```
web/                          网页项目
  股市模拟.html                交付物：单文件游戏
  server.mjs                  本地预览服务器
  prepare-vendor.mjs          把图表库从 node_modules 同步到 vendor/
  vendor/lightweight-charts.js   （生成物，不入版本控制）

desktop/                      桌面打包相关的一切
  README.md                   这一层目录的分工说明
  neutralino.config.json      Neutralino 配置
  neutralino/                 资源同步与产物清理脚本
  resources/                  （生成物）Neutralino 资源目录
  bin/                        （生成物）Neutralino 运行时
  dist/                       （生成物）打包产物
```

真源永远是 `web/`——桌面打包只做拷贝，不改内容，不会出现"改了一份忘了另一份"。

---

## 为什么能这么小

它**不打包浏览器内核**，而是用系统自带的 WebView2——Windows 11 和打满更新的 Windows 10 都已经装了。所以 exe 里只有：Neutralino 运行时 2.32 MB + 你的游戏 0.30 MB。

实测数字：

| 组成 | 大小 |
| --- | --- |
| Neutralino 运行时（`neutralino-win_x64.exe`） | 2.32 MB |
| 游戏 HTML + 图表库 | 0.30 MB |
| **嵌入资源后的成品 exe** | **2.62 MB** |

## 三条命令

```powershell
npm install                 # 装依赖（含 neu CLI，217 KB），并把图表库同步到 web/vendor/
npx neu update              # 一次性下载 Neutralino 各平台运行时，约 8 MB
npm run neutralino:build    # 打包
```

前两条各跑一次即可，之后改完游戏只跑第三条（它会自动重新同步资源）。

产物：

```
desktop\dist\StockSim\StockSim-win_x64.exe    2.62 MB
```

**单文件、自包含。** 构建脚本带了 `--embed-resources`，游戏与图表库都嵌进了 exe；拷到任何地方（哪怕是空目录）双击就能玩，目标机器不需要 Node、不需要任何依赖。

脚本还会自动删掉 `neu build` 顺手生成的 macOS 与 Linux 二进制，让 `desktop/dist/` 里只剩一个可以拷走的东西。

## 运行时试跑（不打包）

```powershell
npm run neutralino:run
```

## 三个已经踩掉的坑

**1. `documentRoot` 必须指向包内的 `/resources/`，否则页面根本打不开。**
这是最严重的一个：Neutralino 打包时会保留 `resources/` 这层目录名，`documentRoot` 要指向它。写成 `"/"` 的话，服务器会在包根去找 `index.html`，于是**所有资源都返回 404**，WebView 里只显示"找不到 127.0.0.1 页面"。从 2.3 MB 的 exe 里看不出任何异常，进程活着、窗口标题也对。正确写法见 [neutralino.config.json](../desktop/neutralino.config.json)：`documentRoot: "/resources/"` + `url: "/"`。

**2. 端口必须固定，否则存档每次都会丢。**
Neutralino 的 `port` 若设成 `0`（随机端口），WebView2 每次启动的 origin 都不一样，而 localStorage 是按 origin 隔离的——结果是**每次打开游戏存档都清空**。所以配置里固定成了 `41888`。测试里专门有一条守着这个不变量。

**3. 图表库必须落在游戏期望的相对路径上。**
游戏加载链的第一级是相对路径 `vendor/lightweight-charts.js`，资源同步脚本把它放在 `resources/vendor/lightweight-charts.js`，相对位置与 `web/` 里完全一致，所以桌面版离线时也有完整 K 线图。放错了不会报错，只会静默退回内置的 Canvas 简易图——测试里也守着这条。

> 为什么用 `vendor/` 而不是 `node_modules/`：这个 HTML 是能单独拷走的交付物，不该知道 npm 的目录结构。`web/prepare-vendor.mjs` 负责从 `node_modules` 把库同步过去，挂在 npm 的 `postinstall` 上。

## 怎么自查打包结果

上面第 1 条说明：**"进程活着、窗口标题正确"完全不能证明页面加载成功**。真正的验证只有一个——把页面内容取回来：

```powershell
# 启动 desktop\dist\StockSim\StockSim-win_x64.exe 后：
curl.exe -s -o NUL -w "%{http_code}" http://127.0.0.1:41888/
```

返回 `200` 才算正常；返回 `404` 就是 `documentRoot` 写错了，具体原因可以在 exe 同目录的 `neutralinojs.log` 里看到（配置里已开启 `writeToLogFile`）。

顺带一提，默认的窗口标题取自配置而非页面，所以标题正确与否和页面是否加载成功没有任何关系。

`npm test` 里有一条端到端用例会自动做这件事：它拉起打包好的 exe、用 HTTP 取回首页、断言页面里含游戏内核脚本。它会在端口已被残留实例占用时直接失败——避免对着旧进程"假通过"。
